Privacy Policy – Bot Bridge

Chrome extension version 1.0.5 · Last updated: 9 November 2026

Summary

The extension's own network traffic goes only to the bridge app you run on your computer, at http://127.0.0.1. The extension does not send page data to the developer. There is no analytics, tracking, advertising, or account.

This is not an end-to-end offline guarantee. The bridge gives command results to the AI assistant you chose. That assistant may process data off your device under its own privacy policy. Read that policy before you connect an assistant.

What the extension does

Bot Bridge lets your own AI assistant (for example Grok Bot) control your Chrome browser. Your assistant sends commands to a bridge app (bridge.py) on your computer. After you consent, the extension picks those commands up from the bridge and carries them out: opening and switching tabs, reading pages, clicking, typing, scrolling, and taking screenshots.

Nothing is fetched from the bridge until you tick the notice in the popup. You can switch the extension off, revoke consent, or uninstall it. Revoking consent or switching off stops new commands. Placing named local files into pages is part of that notice (version 3). An update that changes the notice asks you to agree again.

Data the extension handles

Only when a command asks for it, the extension reads data and passes it to the local bridge:

  • Web history: URLs and titles of your open tabs, and the URL and title returned with later commands.
  • Website content: visible text, a list of buttons, links, and form fields (including values), and screenshots of the visible part of a tab.
  • Information that can be inside that content. The extension does not have a separate health, finance, location, or mail feature, and it does not call the geolocation API. It also does not filter page content. A page, form, or screenshot can therefore include, when you ask the assistant to read or capture it:
    • personally identifiable information, such as names, email addresses, phone numbers, usernames, or account numbers
    • personal communications visible on a page, such as email or chat text
    • financial or payment details visible on a page or in a form field
    • health information visible on a page
    • location text, such as an address on a page or in a URL
    • authentication information, described below

The extension does not record a separate stream of your own clicks, mouse movements, or keystrokes. It performs the actions a command requests and returns the result of those actions.

Password masking, and what it does not cover

When the extension reads a page (get_page) or returns the result of a click or type on a field, it replaces the value with ••• only for:

  • input fields whose type is password, and
  • fields whose autocomplete token is current-password or new-password.

That masking does not apply to:

  • the rest of the page text, including a password or code the page shows as ordinary text
  • screenshots (they show whatever is on screen, including a password the page has revealed)
  • other fields, including usernames, one-time codes, and card numbers
  • the text of a type command. Your assistant supplies that text so the extension can enter it. The result shown back for a masked field is •••, but the command itself contains what you asked the assistant to type

Files you name

When a command names a file on the computer where the bridge is running, the bridge reads that regular file and the extension places those bytes into a file input or a drop target on the page. This is not a general view of your disk: there is no directory listing, no glob, and no read of a file the command did not name. There is no default size ceiling. The bridge streams the file and Chrome keeps the resulting file on disk-backed blob storage, so a multi-gigabyte video does not have to sit in the bridge as one base64 string. You can set max_upload_bytes in the bridge config to a positive number if you want a ceiling; 0 or omitting it means unlimited. A transfer that makes no progress for 2 minutes is cancelled. The filename sent to the page is the file's base name, not the full path. A website or Chrome itself can still refuse a file that is larger than that site or that browser build allows.

A symlink is resolved and both the path you named and the real path are reported back to the assistant. Devices, directories, and other non-regular files are refused. The bridge does not log file contents. After the bytes are in the page, the website can upload them off your device if you submit the form or the page uploads on its own. That is the point of choosing a file. The developer does not receive the file.

Paths are on the computer running bridge.py. A file that exists only on an assistant's own computer is not on that machine until you copy it there with the file-transfer tool that assistant already uses. This extension is not an automatically connected remote file service.

What is stored

In Chrome (chrome.storage.local) the extension stores only its own settings: the bridge port, the bridge token, the on/off switch, and your consent (including the version of the notice you accepted). The bridge token is a secret that authorizes control of your browser. It is not a password for a website, and it is stored so the extension can reconnect. It is not encrypted by the extension beyond Chrome's local storage and the permissions on the bridge config file.

The bridge stores the same token in ~/.bot-bridge/config.json (or an existing ~/.grok-chrome-bridge/config.json from version 1.0), mode 600, in a directory mode 700 when the operating system allows it. bridge.py serve does not print the token. bridge.py token and bridge.py new-token print it to that terminal. Do not redirect those two commands into a service log. If a log from an older version contains a line Token:, delete the log and run new-token.

Who receives the data

  • The bridge on your computer receives command results and makes them available to the AI assistant you chose to connect. That handoff is the extension's single purpose. The assistant may then process the data off your device. What it does is governed by that assistant's privacy policy, which this policy does not control and does not certify.
  • The developer does not receive page contents, screenshots, tab lists, or the bridge token. The developer does not sell this data and does not use it for advertising, creditworthiness, or lending.

Saying that the developer does not receive the data is not a claim that the data stays on your device after your assistant receives it.

Limited Use

Bot Bridge complies with the Chrome Web Store User Data Policy, including the Limited Use requirements, for data this extension handles.

That data is used only to carry out the browser actions you request through your chosen assistant, and to keep the connection you configured (port, token, on/off, consent). The extension transfers command results only to the bridge on your computer so that assistant can perform those actions. The transfer is necessary for this single purpose and happens only after the consent in the popup. The data is not sold. It is not used or transferred by this extension for advertising, creditworthiness, or lending. The developer does not read page contents.

This statement describes Bot Bridge. It does not certify how a third-party assistant later uses data under that assistant's own policy.

Security

  • The extension connects only to 127.0.0.1. The bridge listens only on 127.0.0.1.
  • The loopback connection is ordinary HTTP. Chrome's User Data FAQ (question 16) says the secure-handling requirement does not apply to transmissions between an extension and a native program on the same computer. This policy does not claim that the hop is encrypted. Other programs on the computer that have the token can send commands. TLS is not a substitute for keeping the token private.
  • Every request needs the token. The bridge rejects a Host header that is not loopback, and it rejects web-page Origin values. Those checks do not stop a local program that already has the token.
  • The Chrome Web Store package contains its code. Commands are data (a command name, URL, selector, or text) passed to functions in the package. The store package has no eval and does not load remote scripts. URLs it opens are http, https, file, or about:blank.
  • The developer build in the source tree can run an optional eval command. That build is not the store package. Leave it off unless you mean to run arbitrary JavaScript in the page.
  • A screenshot is written to disk only when the command names a file path. That write uses your user account and is not limited to a single folder. Do not point it at a path you do not want replaced.

Retention and deletion

The extension does not keep copies of page content or screenshots. Settings stay in Chrome until you change them, revoke consent, or uninstall the extension, which deletes the extension's storage. Delete the bridge config file to remove the token from disk. Rotate it with bridge.py new-token if it may have been logged.

Datenschutzerklärung – Bot Bridge

Chrome-Erweiterung Version 1.0.5 · Stand: 9. November 2026

Kurz gesagt

Der eigene Netzwerkverkehr der Erweiterung geht nur an die Bridge-App, die du auf deinem Computer betreibst, unter http://127.0.0.1. Die Erweiterung sendet Seitendaten nicht an den Entwickler. Keine Analyse, kein Tracking, keine Werbung, kein Konto.

Das ist keine Garantie, dass alles auf dem Gerät bleibt. Die Bridge gibt Befehlsresultate an den KI-Assistenten weiter, den du gewählt hast. Dieser Assistent kann Daten ausserhalb deines Geräts verarbeiten, nach seiner eigenen Datenschutzerklärung. Lies diese, bevor du einen Assistenten verbindest.

Was die Erweiterung tut

Bot Bridge erlaubt deinem eigenen KI-Assistenten (zum Beispiel Grok Bot), deinen Chrome-Browser zu bedienen. Dein Assistent schickt Befehle an eine Bridge-App (bridge.py) auf deinem Computer. Nach deiner Zustimmung holt die Erweiterung diese Befehle ab und führt sie aus: Tabs öffnen und wechseln, Seiten lesen, klicken, tippen, scrollen und Screenshots machen.

Es wird nichts von der Bridge geholt, bevor du den Hinweis im Popup ankreuzt. Du kannst die Erweiterung ausschalten, die Zustimmung widerrufen oder sie deinstallieren. Widerruf oder Ausschalten stoppt neue Befehle. Benannte lokale Dateien in Seiten zu setzen gehört zu diesem Hinweis (Version 3). Ein Update, das den Hinweis ändert, verlangt eine erneute Zustimmung.

Welche Daten die Erweiterung verarbeitet

Nur wenn ein Befehl es verlangt, liest die Erweiterung Daten und gibt sie an die lokale Bridge weiter:

  • Webverlauf: URLs und Titel deiner offenen Tabs sowie URL und Titel, die spätere Befehle zurückgeben.
  • Website-Inhalte: sichtbarer Text, eine Liste von Buttons, Links und Formularfeldern (inklusive Werten) und Screenshots des sichtbaren Bereichs eines Tabs.
  • Angaben, die in diesen Inhalten stehen können. Die Erweiterung hat keine eigene Gesundheits-, Finanz-, Standort- oder Mail-Funktion und ruft die Geolocation-API nicht auf. Sie filtert Seiteninhalte auch nicht. Eine Seite, ein Formular oder ein Screenshot kann deshalb Folgendes enthalten, wenn du den Assistenten bittest, es zu lesen oder aufzunehmen:
    • personenbezogene Angaben wie Namen, E-Mail-Adressen, Telefonnummern, Benutzernamen oder Kontonummern
    • persönliche Kommunikation, die auf einer Seite sichtbar ist, etwa E-Mail- oder Chat-Text
    • Finanz- oder Zahlungsangaben, die auf einer Seite oder in einem Feld sichtbar sind
    • Gesundheitsangaben, die auf einer Seite sichtbar sind
    • Standorttext, etwa eine Adresse auf einer Seite oder in einer URL
    • Authentifizierungsangaben, wie unten beschrieben

Die Erweiterung zeichnet keinen eigenen Strom deiner Klicks, Mausbewegungen oder Tastatureingaben auf. Sie führt die Aktionen aus, die ein Befehl verlangt, und gibt das Resultat dieser Aktionen zurück.

Passwort-Maskierung und ihre Grenzen

Beim Lesen einer Seite (get_page) und im Resultat von Klick oder Tippen ersetzt die Erweiterung den Wert durch ••• nur bei:

  • input-Feldern mit Typ password und
  • Feldern, deren Autocomplete-Token current-password oder new-password ist.

Diese Maskierung gilt nicht für:

  • den übrigen Seitentext, auch wenn dort ein Passwort oder Code als normaler Text steht
  • Screenshots (sie zeigen, was auf dem Bildschirm steht, inklusive eines von der Seite eingeblendeten Passworts)
  • andere Felder, inklusive Benutzernamen, Einmalcodes und Kartennummern
  • den Text eines Tipp-Befehls. Dein Assistent liefert diesen Text, damit die Erweiterung ihn eintragen kann. Das zurückgegebene Resultat eines maskierten Feldes ist •••, der Befehl selbst enthält aber, was du tippen lassen wolltest

Dateien, die du nennst

Wenn ein Befehl eine Datei auf dem Computer nennt, auf dem die Bridge läuft, liest die Bridge diese reguläre Datei und die Erweiterung setzt die Bytes in ein Dateifeld oder ein Drop-Ziel auf der Seite. Das ist keine allgemeine Sicht auf deine Festplatte: kein Verzeichnislisting, kein Glob und kein Lesen einer Datei, die der Befehl nicht nennt. Es gibt keine Standard-Grössengrenze. Die Bridge streamt die Datei, und Chrome hält die entstandene Datei in einem Blob, der auf die Festplatte ausgelagert werden kann, statt sie als einen Base64-String im Speicher zu halten. max_upload_bytes in der Bridge-Konfiguration setzt eine optionale Obergrenze; 0 oder das Weglassen bedeutet unbegrenzt. Eine Übertragung ohne Fortschritt für 2 Minuten wird abgebrochen. Der Dateiname, der an die Seite geht, ist der Basisname, nicht der volle Pfad. Eine Website oder Chrome selbst kann eine Datei trotzdem ablehnen, wenn sie grösser ist, als diese Seite oder dieser Browser zulässt.

Ein Symlink wird aufgelöst, und sowohl der genannte Pfad als auch der reale Pfad werden dem Assistenten gemeldet. Geräte, Verzeichnisse und andere nicht-reguläre Dateien werden abgelehnt. Die Bridge schreibt keine Dateiinhalte ins Log. Sobald die Bytes in der Seite sind, kann die Website sie ausserhalb deines Geräts hochladen, wenn du das Formular sendest oder die Seite selbst hochlädt. Genau dafür wählt man eine Datei. Der Entwickler erhält die Datei nicht.

Pfade liegen auf dem Computer, auf dem bridge.py läuft. Eine Datei, die nur auf dem Computer des Assistenten existiert, ist dort nicht, bis du sie mit dem Dateitransfer kopierst, den dieser Assistent bereits benutzt. Diese Erweiterung ist kein automatisch verbundener Ferndienst für Dateien.

Was gespeichert wird

In Chrome (chrome.storage.local) speichert die Erweiterung nur ihre eigenen Einstellungen: Bridge-Port, Bridge-Token, Ein/Aus-Schalter und deine Zustimmung (inklusive der Version des Hinweises, dem du zugestimmt hast). Der Bridge-Token ist ein Geheimnis, das die Steuerung deines Browsers erlaubt. Er ist kein Website-Passwort. Er wird gespeichert, damit die Erweiterung sich wieder verbinden kann. Die Erweiterung verschlüsselt ihn nicht über Chromes lokalen Speicher und die Dateirechte der Bridge-Konfiguration hinaus.

Die Bridge speichert denselben Token in ~/.bot-bridge/config.json (oder einer bestehenden ~/.grok-chrome-bridge/config.json aus Version 1.0), Modus 600, in einem Verzeichnis Modus 700, soweit das Betriebssystem das zulässt. bridge.py serve gibt den Token nicht aus. bridge.py token und bridge.py new-token geben ihn in diesem Terminal aus. Leite diese beiden Befehle nicht in ein Dienst-Log um. Wenn ein Log einer älteren Version eine Zeile Token: enthält, lösche das Log und führe new-token aus.

Wer die Daten erhält

  • Die Bridge auf deinem Computer erhält die Befehlsresultate und stellt sie dem KI-Assistenten bereit, den du verbunden hast. Diese Weitergabe ist der einzige Zweck der Erweiterung. Der Assistent kann die Daten danach ausserhalb deines Geräts verarbeiten. Was er damit tut, regelt seine eigene Datenschutzerklärung. Diese Erklärung steuert das nicht und bestätigt es nicht.
  • Der Entwickler erhält keine Seiteninhalte, Screenshots, Tab-Listen oder den Bridge-Token. Der Entwickler verkauft diese Daten nicht und nutzt sie nicht für Werbung, Bonität oder Kreditvergabe.

Dass der Entwickler die Daten nicht erhält, bedeutet nicht, dass die Daten auf deinem Gerät bleiben, nachdem dein Assistent sie erhalten hat.

Limited Use

Bot Bridge hält die Chrome-Web-Store-Richtlinie zu Nutzerdaten ein, einschliesslich der Anforderungen zur beschränkten Nutzung (Limited Use), für Daten, die diese Erweiterung verarbeitet.

Diese Daten werden nur verwendet, um die Browser-Aktionen auszuführen, die du über deinen gewählten Assistenten verlangst, und um die von dir eingerichtete Verbindung zu halten (Port, Token, Ein/Aus, Zustimmung). Die Erweiterung gibt Befehlsresultate nur an die Bridge auf deinem Computer weiter, damit dieser Assistent die Aktionen ausführen kann. Die Weitergabe ist für diesen einzigen Zweck nötig und erfolgt erst nach der Zustimmung im Popup. Die Daten werden nicht verkauft. Diese Erweiterung nutzt oder übermittelt sie nicht für Werbung, Bonität oder Kreditvergabe. Der Entwickler liest keine Seiteninhalte.

Diese Aussage beschreibt Bot Bridge. Sie bestätigt nicht, wie ein Assistent eines Dritten die Daten später nach seiner eigenen Erklärung verwendet.

Sicherheit

  • Die Erweiterung verbindet sich nur mit 127.0.0.1. Die Bridge lauscht nur auf 127.0.0.1.
  • Die Loopback-Verbindung ist gewöhnliches HTTP. Die FAQ zu Nutzerdaten von Chrome (Frage 16) sagt, dass die Anforderung an sichere Verarbeitung nicht für Übertragungen zwischen einer Erweiterung und einem nativen Programm auf demselben Computer gilt. Diese Erklärung behauptet nicht, dass dieser Hop verschlüsselt ist. Andere Programme auf dem Computer, die den Token haben, können Befehle senden. TLS ersetzt nicht den Schutz des Tokens.
  • Jede Anfrage braucht den Token. Die Bridge lehnt einen Host-Header ab, der nicht Loopback ist, und sie lehnt Origin-Werte von Webseiten ab. Diese Prüfungen stoppen kein lokales Programm, das den Token bereits hat.
  • Das Chrome-Web-Store-Paket enthält seinen Code. Befehle sind Daten (Befehlsname, URL, Selektor oder Text) und gehen an Funktionen im Paket. Das Store-Paket hat kein eval und lädt keine externen Skripte. URLs, die es öffnet, sind http, https, file oder about:blank.
  • Die Entwicklerfassung im Quellbaum kann einen optionalen eval-Befehl ausführen. Diese Fassung ist nicht das Store-Paket. Lass sie aus, ausser du willst beliebiges JavaScript in der Seite ausführen.
  • Ein Screenshot wird nur dann auf die Festplatte geschrieben, wenn der Befehl einen Dateipfad nennt. Dieser Schreibvorgang läuft unter deinem Benutzerkonto und ist nicht auf einen einzelnen Ordner beschränkt. Nenne keinen Pfad, den du nicht ersetzen willst.

Speicherdauer und Löschung

Die Erweiterung behält keine Kopien von Seiteninhalten oder Screenshots. Einstellungen bleiben in Chrome, bis du sie änderst, die Zustimmung widerrufst oder die Erweiterung deinstallierst (dabei wird der Speicher der Erweiterung gelöscht). Lösche die Bridge-Konfigurationsdatei, um den Token von der Festplatte zu entfernen. Erzeuge einen neuen mit bridge.py new-token, wenn er in einem Log gestanden haben könnte.
